# 2026-06-24 RetryとDead Letter Queue

## 成果物

### Retry対象の処理をinterfaceで表す

```java
@FunctionalInterface
interface RetryableTask {
    void run() throws Exception;
}
```

### RetryExecutor

```java
class RetryExecutor {
    void execute(RetryableTask task, int maxAttempts, long initialDelayMillis) throws Exception {
        long delay = initialDelayMillis;

        for (int attempt = 1; attempt <= maxAttempts; attempt++) {
            try {
                task.run();
                return;
            } catch (Exception e) {
                if (attempt == maxAttempts) {
                    throw e;
                }
                Thread.sleep(delay);
                delay *= 2;
            }
        }
    }
}
```

### Dead Letter Queue

```java
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

record DeadLetterMessage(
        NotificationMessage message,
        String reason,
        LocalDateTime failedAt
) {}

class DeadLetterQueue {
    private final List<DeadLetterMessage> messages = new ArrayList<>();

    void add(NotificationMessage message, Exception cause) {
        messages.add(new DeadLetterMessage(message, cause.getMessage(), LocalDateTime.now()));
    }

    List<DeadLetterMessage> findAll() {
        return List.copyOf(messages);
    }
}
```

### Consumerで使う例

```java
class ReliableNotificationConsumer {
    private final RetryExecutor retryExecutor = new RetryExecutor();
    private final DeadLetterQueue deadLetterQueue = new DeadLetterQueue();

    void consume(NotificationMessage message) {
        try {
            retryExecutor.execute(() -> send(message), 4, 1_000L);
        } catch (Exception e) {
            deadLetterQueue.add(message, e);
        }
    }

    private void send(NotificationMessage message) {
        System.out.println("send: " + message);
    }
}
```

## 実務への接続

通知処理はメール送信、DB保存、WebSocket配信など外部要因で失敗しやすい。リトライ可能な失敗は自動復旧を試み、一定回数失敗したものはDLQへ分離して手動確認できるようにする。

## リファクタ観点

- DLTログに `eventType`、`expenseId`、`traceId`、失敗理由を必ず残す
- 同じイベントを再処理しても二重通知や二重登録にならないか確認する
- メール送信成功後にDB保存が失敗した場合など、部分成功の扱いを決める
- Retry対象を処理単位で分け、失敗箇所を特定しやすくする

### 作業所感
